## Contributing

Thank you for contributing to Git Engineering Lab.

---

## Goal

Keep the repository:

- Practical
- Easy to search
- Accurate
- Up to date

---

## Before Opening a PR

Please ensure:

- Documentation is technically correct.
- Examples are tested.
- Markdown formatting is consistent.
- Existing structure is preserved.

---

## Documentation Principles

Every document should answer:

1. What is it?
2. Why should I use it?
3. When should I use it?
4. When should I NOT use it?
5. Common mistakes
6. Best practices
7. Related commands

---

## Writing Style

Use:

- Short paragraphs
- Clear headings
- Practical examples
- Simple English

Avoid:

- Long introductions
- Personal opinions
- Unverified information
- Duplicate explanations

---

## Pull Request Guidelines

A Pull Request should focus on **one topic only**.

Good:

- Improve `git restore`
- Fix typo
- Add examples

Avoid:

- Update 15 files
- Rewrite multiple topics
- Mix formatting and content changes

---

## File Naming

Use:

```md
kebab-case.md
```

Example:

```md
stage-and-commit.md
```

---
